# 스펙에서 실제 설명으로 이어지는 예시

이 문서는 목표형 스펙을 실제 설명으로 확장하는 수준, 의미상 섹션과 표시용 소제목의 경계, 변경 수준을 한 사례 안에서 보여준다.

## 이 예시의 자료

- U1: 선택 가능한 증류 경로가 중심이고 자원 관리는 그 기능을 뒷받침하는 하위 설명이라는 사용자 의도다.
- M2: 티처 체크포인트를 CPU에 읽은 뒤 활성 경로에 필요한 모듈을 선별해 GPU로 옮긴다. LM만 사용하면 이미지 인코더와 텍스트 디코더가 필요하고, LM과 ITM을 함께 사용하면 텍스트 인코더와 ITM 헤드도 필요하다.
- M3: 같은 학습 step에서는 티처 이미지 인코더의 출력 토큰 임베딩을 활성 경로가 공유하고, 다음 step의 입력은 새로 계산한다.

이 요약은 **이 예시에서 제공하는 사실 자료**다. 새 보고서의 구현 증거로 재사용하지 말고, 새 보고서에서는 그 문서의 실제 원자료를 확인한다.

<a id="expansion"></a>
## 목표에서 실제 설명으로 확장

**S8 · 증류 경로를 선택·조합하는 통합 증류기**

핵심: 필요한 증류 방식을 선택해 함께 사용할 수 있도록 구성한 통합 증류기의 구현 방식을 설명한다.

우선 참조: U1 — 선택 기능을 중심에 둘 의도. M2 — 모듈 선별과 적재 순서. M3 — 같은 step의 이미지 인코딩 공유.

스펙의 핵심은 섹션의 설명 목표를 압축한다. 플랜은 이 목표를 다음처럼 동작·이유·조건이 보이는 실제 설명으로 확장한다.

**S8 / P2 · 메모리 관리**

실제 설명: 체크포인트를 CPU에 읽은 뒤 선택한 증류 경로에 필요한 티처 모듈을 남겨 GPU로 옮긴다. LM만 사용할 때는 이미지 인코더와 텍스트 디코더가 필요하고, ITM을 함께 사용하면 텍스트 인코더와 ITM 헤드도 필요하다. 선택하지 않은 경로의 모듈을 적재하지 않는 이유는 GPU 메모리를 차지하지 않게 하기 위해서다.

근거: M2. 배치: S8의 표시용 소제목 아래, 중심 기능 소개 다음.

**S8 / P3 · 계산 재사용**

실제 설명: 같은 학습 step에서 티처 이미지 인코딩을 한 번 수행하고 출력 토큰 임베딩을 활성화된 증류 경로에 전달한다. 각 경로는 이 임베딩으로 필요한 티처 정보를 계산한다. 다음 step의 입력은 새로 인코딩한다.

근거: M3. 배치: P2 다음.

`필요한 모듈만 적재한다`나 `계산을 재사용한다`만 반복하면 목표형 문장에 머문다. P2와 P3처럼 무엇을 어떤 순서로 수행하는지, 선택에 따라 무엇이 달라지는지, 공유 범위가 어디까지인지가 있어야 실제 설명이다.

<a id="headings"></a>
## 섹션과 표시용 소제목

메모리 관리와 계산 재사용은 S8의 구현을 풀어 설명하는 표시용 소제목이다. 별도의 목표·범위를 맡지 않으므로 소제목이 생겼다는 이유만으로 새 S를 배정하지 않는다.

세 증류 경로의 전체 역할을 비교하는 요약은 계산 재사용의 자식이 아니다. `증류 경로별 역할 요약`을 메모리 관리·계산 재사용과 같은 S8의 형제 구획으로 두어 통합 증류기 전체를 정리한다. 반대로 스펙 단계부터 별도 목표·범위를 배정한 하위 S라면 표시 크기와 관계없이 그 S의 핵심·참조·점검 대응을 별도로 유지한다.

<a id="changes"></a>
## 변경 수준 판정

| 변경 | 판정과 처리 |
|---|---|
| 이미 있는 설명을 `경로 선택`, `메모리 관리`, `계산 재사용` 소제목으로 묶는다. | 의미를 유지한 표현 보완이다. 관련 체크를 다시 확인하고 현재 단계의 전체 검토에 포함한다. |
| 승인된 플랜에 없던 필수 전송 과정을 메모리 관리 설명에 추가한다. | 핵심은 같아도 필수 설명이 달라지는 writing-plan 변경이다. 영향받는 플랜과 원고의 구체적 수정안을 묶어 승인받는다. |
| 목표를 통합 증류기 구현에서 장치별 배포 적합성 평가까지 확대한다. | 목표·범위가 달라지는 spec 변경이다. spec 수정안과 관련 플랜의 영향 범위를 함께 제시한다. |

<a id="presentation"></a>
## 같은 내용을 두 방식으로 표현

결과보고서형에서는 핵심과 선택지 차이를 빠르게 훑을 수 있게 배치한다.

**필요한 티처 모듈만 GPU에 적재한다.** 체크포인트를 CPU에서 읽은 뒤, 선택한 증류 경로에 필요한 모듈을 남겨 GPU로 옮긴다.

- **LM만 사용:** 이미지 인코더와 텍스트 디코더를 적재한다.
- **LM과 ITM 사용:** 여기에 텍스트 인코더와 ITM 헤드를 추가로 적재한다.

논문형에서는 같은 비교를 연결된 문장으로 설명한다.

티처는 선택한 증류 경로에 필요한 모듈만 GPU에 적재하도록 구성하였다. 체크포인트를 CPU에서 읽은 뒤 필요한 모듈을 선별해 GPU로 옮겼으며, LM만 사용할 때는 이미지 인코더와 텍스트 디코더를 적재하였다. ITM을 함께 사용하는 경우에는 텍스트 인코더와 ITM 헤드를 추가로 적재하였다.

두 표현은 CPU 로드 뒤 선별하고 GPU로 이동하는 순서와 LM·LM+ITM의 모듈 구성을 동일하게 유지한다. 표현 방식에 따라 배치만 달라진다. 두 버전 동시 출력, 항상 마지막에 두는 표, 고정 소제목 수는 일반 규칙이 아니다.

<a id="repairs"></a>
## 경계를 바로잡는 수정 사례

| 미충족 표현 또는 배치 | 수정과 이유 |
|---|---|
| “인코더의 특징을 여러 경로가 활용한다.” | “티처 이미지 인코더의 출력 토큰 임베딩을 활성화된 증류 경로에서 공유한다.”로 대상을 특정한다. |
| “계산한 임베딩을 학습 중 계속 재사용한다.” | “같은 학습 step에서 계산한 출력 토큰 임베딩을 활성화된 증류 경로에서 공유한다. 다음 step에서는 새 입력을 다시 인코딩한다.”로 범위를 보존한다. |
| 세 경로 전체의 역할 요약표를 `계산 재사용` 아래에 둔다. | 표를 같은 수준의 `증류 경로별 역할 요약` 아래로 옮긴다. 표는 계산 재사용만이 아니라 S8 전체를 정리하기 때문이다. 같은 내용을 재배치하는 표현 보완이며 새 스펙 섹션을 요구하지 않는다. |

이 사례들은 판정 경계를 설명한다. 현재 작업의 사용자 승인이나 실제 오류 이력을 뜻하지 않는다.

# Report Writing Skill

자료·기존 초안·작성 조건을 받아, 글감 브레인스토밍 → 스펙시트 → 라이팅 플랜 → 원고 작성으로 이어지는 스킬을 개발한다. 보고서 전반에 적용할 지침을 다루며, 첫 적용 대상은 결과보고서다.

## 현재 개발 상태

2026-09-09 기준이다. Git은 파일의 변경 이력을 관리하고, 이 절은 현재 단계와 다음 작업을 기록한다.

| 항목 | 상태 |
|---|---|
| 개발 저장소 | `report-writing-skill/`를 별도 로컬 Git 저장소로 구성 |
| 설계 | 큰 구조를 정리했고, 그룹 6·7 및 기존 초안 진입·재개 세부 논의안을 검토 중 |
| 첫 예시 | 통합 증류기 사례를 원고까지 작성하고 사용자 검토를 받음 |
| 사용자 피드백 | 원고는 의도에 맞음. 플랜 해설 후 U·M·P 등의 참조 표기 유지에 동의 |
| 구현 계획 | 작성 전. 남은 결정과 체크 기준을 정리한 뒤 작성 |
| 실제 스킬 | `SKILL.md` 구현·설치 전 |

이번 저장소 구성은 개발 폴더 정리와 로컬 Git 관리를 위한 것이다. 원고 예시의 긍정적 평가나 저장소 구성에 대한 동의를 스킬 전체의 최종 승인으로 확대하지 않는다.

## 먼저 읽을 문서

1. [기준 설계 스펙](docs/superpowers/specs/2026-09-09-report-writing-skill-design.md): 구현할 요구사항과 결정 상태. §0은 네 문서의 참조 관계, §6은 후속 사항을 정리한다.
2. [통합 증류기 연결 예시](docs/superpowers/specs/2026-09-09-integrated-distiller-writing-example.md): 자료 풀 → 스펙 → 실제 설명을 담은 플랜 → 원고의 구체적인 모습.
3. [예시 작업 메모](docs/superpowers/specs/2026-09-09-integrated-distiller-writing-example-notes.md): 자료 대조, 선택 이유, 자체 점검, 사용자 피드백과 후속 해석.
4. [과거 비판적 검토](docs/superpowers/specs/2026-09-09-report-writing-skill-critical-review.md): 이전 스펙의 모호함과 보완 제안. 현재 미해결 작업 목록으로 그대로 사용하지 않는다.

기준 스펙은 첫 번째 문서 하나다. 나머지는 예시·판단 근거·검토 기록으로 참조한다. 네 문서는 기존 작업 폴더에서 이 저장소로 이동했으며, 이후 이 위치에서 갱신한다.

## 유지할 결정

- 현재 범위는 단일 에이전트가 사용하는 작성 스킬 하나다. 별도의 피드백 스킬과 그 서브에이전트 방식은 후속 작업으로 보류한다.
- 사용자가 스킬을 명시적으로 호출하는 방식으로 개발한다. AGENTS.md를 통한 자동 실행은 넣지 않는다.
- 스펙은 섹션별 제목·핵심·참조 포인터로 짧게 유지한다. 라이팅 플랜은 연결된 자료를 읽어 실제 설명으로 확장한다.
- 에이전트가 섹션별 점검을 수행하고, 사용자는 단계 전체 산출물의 내용·구조를 검토한다. 이미 승인한 범위는 반복해서 승인받지 않는다.
- 피규어는 생성하지 않는다. 필요한 그림의 의도·내용·스케치 구성과 원고의 캡션·각주를 준비한다.
- U(User), M(Material), P(Plan), S(Section) 표기는 첫 예시에서 유지하며, 뜻을 처음에 안내한다.

세부 기준과 예외는 기준 스펙을 따른다. 특정 예시의 소제목 수나 표 배치를 모든 보고서의 고정 규칙으로 일반화하지 않는다.

## 다음 작업

1. 기준 스펙 §4.1~§4.5의 그룹 6·7 논의안(공통 기준 8개·형식별 적용·짧은 비교 예시)을 검토한다. 필요한 보조 사례로 남은 선별·표현 판단을 확인한다.
2. §3.6~§3.7의 진입·재개와 인계 경계 논의안을 검토한다. 승인 이력이 없는 기존 초안의 첫 검토를 한 묶음으로 받을지 사용자 선택을 기다린다.
3. 스킬의 호출 이름과 실행 시 생성할 자료·산출물의 저장 구성을 정한다. 이번에 정한 **개발 저장소의 폴더 구성**과 구별한다.
4. 최종 설계를 바탕으로 `superpowers:writing-plans`를 사용하여 [구현 계획 폴더](docs/superpowers/plans/)에 하나의 스킬 구현 계획을 작성한다. `Spec`은 기준 설계 문서를 가리킨다.
5. 구현 계획 검토 후 [스킬 개발 폴더](skills/)에서 실제 스킬을 구현·검증한다.

Superpowers의 구현 계획은 이 스킬을 어떻게 제작할지 정한다. 스킬 실행 중 만드는 보고서 라이팅 플랜(P 항목)은 어떤 내용을 어떤 순서로 쓸지 정한다.

## 작업을 이어갈 때

이 README와 기준 스펙의 결정 상태를 읽고, 관련 예시·피드백을 확인한다. 현재 대화를 계속하면서 명령의 작업 경로를 이 저장소로 지정할 수 있다.

저장소 안에서는 `git status`로 변경 파일을, `git log --oneline`으로 기록한 변경 이력을 확인한다. 상위 보고서 작업 폴더에서는 `git -C .\report-writing-skill status`로 이 저장소를 지정할 수 있다. 개발 단계가 바뀌면 이 README의 현재 상태와 다음 작업도 함께 갱신한다.

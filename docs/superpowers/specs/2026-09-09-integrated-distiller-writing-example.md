# 통합 증류기 · 네 단계 연결 예시

버전: v0.1 · 2026-09-09 · 첫 사용자 검토 반영: 표기 안내 추가

2026-09-10 이관: 기준 스펙의 두 표현 방식 비교를 §4 끝으로 옮겼다. 기존 예시 본문과 검토 상태는 유지한다.

보고서 작성 스킬의 설계를 검토하기 위한 첫 실제 예시다. 같은 글감을 자료 풀 → 스펙 → 라이팅 플랜 → 원고로 연결했다. 네 산출물을 함께 비교하기 위한 검토 초안이며, 각 단계의 내용·구조를 이미 승인받았다는 뜻은 아니다.

각 단계 아래의 **사용자 코멘트**에 의견을 남기거나, 고칠 문장 바로 아래에 적으면 된다. 예시 수정과 공통 지침 후보에 반영할 내용을 함께 정리할 예정이다. 상세한 자료 대조와 자체 점검은 [작업 메모](2026-09-09-integrated-distiller-writing-example-notes.md)에 두었다.

이 예시의 참조 표기는 다음 뜻으로 사용한다. 약자와 번호는 항목을 다시 찾고 연결하기 위한 이름이다.

| 표기 | 약자 | 가리키는 항목 |
|---|---|---|
| S | Section | 스펙에서 정한 의미상 섹션. S8은 이번 보고서의 8절이다. |
| P | Plan | 라이팅 플랜의 항목. 설명·그림·표·연결 문장을 포함하며, 반드시 원고 한 문단과 같지는 않다. |
| U | User | 사용자 의도·강조점·피드백 기록 |
| M | Material | 원고·코드·실험 기록 등 설명을 구성하는 자료 |

예를 들어 `P2 — M1·M2`는 플랜 항목 P2의 설명이 자료 M1·M2에 연결된다는 뜻이다. 사용자는 해설 후 이 표기 방식을 유지하는 데 동의했다.

## 1. 글감 브레인스토밍 결과

이번에는 기존 피드백과 대화에서 확인된 의도를 사용했다. 새로운 사용자 답변을 가정하여 추가하지 않았다.

### 작성 조건과 짧은 작성안

- **목적·독자:** 해당 분야에 익숙하지 않은 교수에게, 어떤 증류 기능을 개발했고 어떻게 함께 사용할 수 있게 했는지 설명한다.
- **형식:** 결과보고서형. 중심 기능을 먼저 말하고, 하위 설명은 소제목으로 나눈다. 전문 용어는 대상과 동작이 분명하도록 사용한다.
- **강조점:** 필요한 증류 경로를 설정에서 선택해 조합하는 기능이 중심이다. 메모리 관리와 계산 재사용은 이를 뒷받침한다. 세 경로의 역할은 마지막 표로 정리한다.
- **범위:** 통합 증류기의 구현을 설명한다. 각 증류 방법의 개발 과정과 성능 평가는 각각 앞 절과 뒤 절에서 다룬다. 새 피규어는 설명과 자리만 준비한다.

현재 보고서에서 이 부분의 역할은 다음과 같다. 기존 목차에서 읽어낸 연결이며, 보고서 전체를 새로 승인받는 스펙은 아니다.

| 위치 | 전달할 내용 | 다음 부분과의 연결 |
|---|---|---|
| 앞: ITM·ITC·LM 개발 절 | 각 증류 방식이 전달하는 정보와 개발 결과 | 개별 방식을 함께 사용할 구현이 필요하다. |
| 현재: 통합 증류기 | 증류 경로를 선택하고 필요한 티처 모듈과 계산을 관리한 방식 | 이 구성으로 학습한 학생의 성능을 평가한다. |
| 뒤: 통합 성능 평가 | 학생 baseline 및 BLIP-base와의 비교 | 개선한 점과 남은 한계를 해석한다. |

### 연결된 글감과 원자료

요약 옆에 원문 위치를 남겼다. 플랜을 확장할 때는 해당 원문을 확인하며, 이 목록에 있는 모든 내용을 원고에 넣을 필요는 없다.

**U1 · 현재 사용자 의도** — [현재 피드백의 ‘통합 증류기 디자인’](../../../../리포트%20초안%20피드백0909.md)

> 토글 방식으로 껏다 켜서 필요한 증류기를 선택 가능하게 개발되었다가 핵심이다.

이어지는 피드백은 메모리·컴퓨팅 자원 관리를 하위 제목으로 분류하고, 마지막에 표를 배치하도록 정한다. 문서 위쪽의 전체 피드백은 두괄식, 정확한 공학 용어, 핵심 이해에 필요한 설명의 선별을 요구한다.

**U2 · 설명을 줄일 위치** — [이전 피드백의 ‘통합 학습’ 부분](../../../../report_draft_feedback.md)

> 통합 증류의 서론치고 너무 길다. 이문단 떼라.

이 지시는 온라인 티처와 오프라인 캐시의 차이를 길게 설명하던 도입부에 붙어 있다. 같은 피드백은 필요한 티처 가중치의 선별과 LM 단독·ITC+LM 등의 선택 기능을 포함하도록 요구한다.

**M1 · 현재 원고의 재료** — [현재 보고서 §8](../../../../report_final.md)

> 티처는 체크포인트를 CPU에서 읽은 뒤, 활성화한 증류 경로에 필요한 모듈의 합집합만 남겨 GPU로 이동하도록 구성하였다.

같은 절에 경로별 토글, LM 사용 시 필요한 모듈, 같은 step의 이미지 인코딩 재사용, 세 경로의 요약 표가 있다. 기존 설명을 재사용하되, 중심 기능이 먼저 드러나도록 배치를 바꾼다.

**M2 · 경로 선택과 모듈 적재의 실제 구현** — [derive_teacher_keep](../../../../Distillation_Project/distillation/distill_config.py), [OnlineTeacher의 NEEDS와 초기화](../../../../Distillation_Project/distillation/online_teacher.py), [pretrain의 티처 생성부](../../../../Distillation_Project/pretrain.py)

코드는 `lm`, `itc_target_mix`, `itm`의 활성화 설정으로 필요한 경로를 정한다. 체크포인트를 CPU에 로드한 뒤 필요한 모듈을 남기고, 호출부에서 장치를 옮긴다. LM만 사용하면 이미지 인코더와 텍스트 디코더를 남기며, ITM까지 사용하면 텍스트 인코더와 ITM 헤드가 추가로 필요하다.

**M3 · 같은 step의 이미지 인코딩 공유** — [pretrain의 학습 루프](../../../../Distillation_Project/pretrain.py), [OnlineTeacher.encode_image와 경로별 메서드](../../../../Distillation_Project/distillation/online_teacher.py)

```python
teacher_image_embeds = (
    online_teacher.encode_image(image)
    if (need_embeds and online_teacher is not None) else None
)
```

이 결과를 같은 step의 ITC·LM 계산과 학생 forward 내부의 ITM 티처 계산에 전달한다. 다음 step에서는 그때의 입력으로 다시 계산한다.

**M4 · 세 경로의 학습 반영 방식** — [학생 forward](../../../../Distillation_Project/models/blip_pretrain.py), [target-mix](../../../../Distillation_Project/distillation/target_mix.py), [증류 손실](../../../../Distillation_Project/distillation/losses.py)

ITC는 같은 후보에 대한 정답·모멘텀·티처 분포를 목표 분포로 혼합한다. ITM은 같은 후보들 사이의 티처 판단을 관계 증류 손실로 전달한다. LM은 같은 유효 토큰 위치에서 다음 토큰의 어휘 분포를 전달한다. 학생의 기본 ITC·ITM·LM 학습은 유지된다.

**글감의 선별:** M2·M3의 동작과 조건은 본문에 사용하고, M4는 마지막 표로 압축한다. U2가 지적한 긴 캐시 비교, all-gather 세부 동작, 세 증류의 손실식·개발 이력은 이번 절에서 반복하지 않는다. 원자료와 해당 설명이 있는 앞 절은 계속 참조할 수 있다.

**사용자 코멘트 — 글감·작성 조건**

## 3. 라이팅 플랜

입력은 위 스펙과 작성 조건, 사용자 강조점, 연결된 자료 풀이다. P1~P5는 S8에 속하고 P6는 다음 성능 평가 절로 이어지는 도입이다. 각 항목은 최종 표현보다 실제 설명 내용과 순서를 검토하기 위해 작성했다.

**P1 · 중심 기능과 앞 절의 연결**

ITC target-mix, ITM 관계 증류, LM 증류를 학습 설정에서 각각 선택할 수 있다. 앞 절에서 설명한 방식을 하나의 학생 학습 코드에서 조합한다. 학생의 기본 ITC·ITM·LM 학습을 유지하며, LM 단독 또는 ITC+LM처럼 추가할 증류 경로를 선택한다. — U1·U2, M2·M4

**P2 · 메모리 관리: 필요한 티처 모듈만 GPU에 적재**

체크포인트를 CPU에 읽은 뒤 선택한 증류 경로에 필요한 티처 모듈을 남겨 GPU로 옮긴다. LM만 사용할 때 필요한 모듈은 이미지 인코더와 텍스트 디코더다. ITM을 함께 사용하면 텍스트 인코더와 ITM 헤드도 필요하다. 경로 선택에 따라 사용하지 않는 모듈의 GPU 적재를 생략한다. — M1·M2

**P3 · 계산 재사용: 같은 step의 이미지 인코딩을 공유**

같은 학습 step에서 필요한 티처 이미지 인코딩을 한 번 수행하고, 출력 토큰 임베딩을 활성화된 증류 경로에 전달한다. 각 경로는 이 임베딩으로 자신에게 필요한 티처 정보를 계산한다. 다음 step의 입력은 새로 인코딩한다. — M3

**P4 · 피규어 E-F1의 핵심**

하나의 티처 이미지 인코더 출력이 같은 step의 활성 증류 경로로 나뉘어 전달되는 구조를 보여준다. P3 뒤에 배치할 후보이며, 삽입 필요성은 원고와 함께 검토한다. — M2·M3

**P5 · 증류 경로별 역할 요약: 마지막 표의 실제 내용**

| 증류 경로 | 티처에게서 전달하는 정보 | 학생 학습에 반영하는 방식 |
|---|---|---|
| ITC target-mix | 같은 이미지·텍스트 후보에 대한 유사도 분포 | 정답·모멘텀·티처 분포를 혼합한 목표 분포로 대조 학습 |
| ITM 관계 증류 | 같은 정답·오답 후보들 사이의 상대적 판단 분포 | 기존 일치 판별 학습에 관계 증류 손실 추가 |
| LM 증류 | 같은 유효 토큰 위치의 다음 토큰 어휘 분포 | 기존 토큰 예측 학습에 분포 증류 손실 추가 |

표는 세 경로가 전달하는 정보와 적용 위치를 같은 기준으로 비교한다. 메모리·계산 재사용과 같은 깊이의 ‘증류 경로별 역할 요약’ 소제목 아래에 두어 통합 증류기 전체를 정리한다. 손실식과 실험 결과는 앞 절에서 설명하므로 재수록하지 않는다. — M4, U1

**P6 · 다음 절로 이어지는 설명**

이 구성으로 세 증류를 함께 적용한 학생을 학생 baseline과 BLIP-base에 비교하여, 증류의 효과와 더 큰 모델에 도달한 성능 수준을 평가한다. 이 문장은 다음 성능 평가 절의 도입으로 둔다. — 현재 보고서 §9.1

**사용자 코멘트 — 실제 설명의 충분함·순서·피규어 필요성**

### 8. 증류 경로를 선택·조합하는 통합 증류기

**ITC target-mix, ITM 관계 증류, LM 증류를 설정에서 각각 켜고 꺼 조합할 수 있는 통합 증류기를 구현하였다.** 앞 절에서 설명한 방식을 하나의 학생 학습 코드에서 사용할 수 있으며, LM 단독이나 ITC+LM처럼 필요한 증류를 선택한다. 학생의 기본 ITC·ITM·LM 학습은 유지된다.[^e-config]

#### 메모리 관리: 필요한 티처 모듈만 GPU에 적재

티처 체크포인트를 CPU에 읽은 뒤, 선택한 증류 경로에 필요한 모듈만 남겨 GPU로 옮긴다. 사용하지 않는 티처 모듈은 GPU 메모리를 차지하지 않도록 구성하였다.[^e-memory]

- **LM만 사용:** 이미지 인코더와 텍스트 디코더를 적재한다.
- **LM과 ITM 사용:** 여기에 텍스트 인코더와 ITM 헤드를 추가로 적재한다.

#### 계산 재사용: 같은 step의 이미지 인코딩을 공유

같은 학습 step의 입력 이미지를 티처 이미지 인코더로 한 번 처리하고, 출력 토큰 임베딩을 활성화된 증류 경로에서 공유한다. 각 경로는 이를 이용해 필요한 티처 정보를 계산한다. 다음 step에서는 새 입력을 다시 인코딩한다.[^e-reuse]

> **[그림 E-F1 삽입 예정]**
>
> **그림 E-F1. 활성 증류 경로의 티처 이미지 인코딩 공유.** 같은 학습 step에서 계산한 이미지 토큰 임베딩을 필요한 ITC·ITM·LM 경로에 전달한다. 각 경로의 후속 계산은 학생에게 전달할 정보에 맞게 수행한다.
>
> 주: 이 그림의 step은 입력 배치 하나를 처리하는 학습 반복을 뜻한다.

#### 증류 경로별 역할 요약

선택한 경로가 학생에게 전달하는 정보와 학습에 반영되는 위치는 다음과 같다.[^e-losses]

| 증류 경로 | 티처에게서 전달하는 정보 | 학생 학습에 반영하는 방식 |
|---|---|---|
| ITC target-mix | 같은 이미지·텍스트 후보에 대한 유사도 분포 | 정답·모멘텀·티처 분포를 혼합한 목표 분포로 대조 학습 |
| ITM 관계 증류 | 같은 정답·오답 후보들 사이의 상대적 판단 분포 | 기존 일치 판별 학습에 관계 증류 손실 추가 |
| LM 증류 | 같은 유효 토큰 위치의 다음 토큰 어휘 분포 | 기존 토큰 예측 학습에 분포 증류 손실 추가 |

### 9. 통합 성능 평가와 캡션 분석 · 도입 예시

이 구성으로 세 증류를 함께 적용한 학생을 학생 baseline 및 BLIP-base와 비교하였다. 같은 학생 구조에서 증류로 얼마나 개선되었는지, 더 큰 모델에 어느 정도의 성능 수준으로 도달했는지를 나누어 평가한다.

### 피규어 검토 메모

아래는 그림 제작을 위한 설명이며 위 원고 본문에 그대로 넣는 문단은 아니다. 실제 그림은 생성하지 않았다.

- **설명할 것:** 선택한 증류 경로들이 티처 이미지 인코더의 출력을 어떻게 공유하는가.
- **의도:** 경로마다 이미지 인코딩을 반복할 필요 없이 한 번 계산한 결과를 나누어 쓴다는 구조를 이해시킨다.
- **내용:** 입력 이미지, 티처 이미지 인코더, 공유 토큰 임베딩, ITC·ITM·LM의 경로별 후속 계산. 경로의 활성 여부를 구분한다.
- **간단한 스케치 구성:** 왼쪽에 입력 이미지, 가운데에 티처 이미지 인코더와 출력 임베딩, 오른쪽에 세 경로를 세로로 배치한다. 선택된 경로로 연결되는 화살표를 표시하고 전체를 ‘같은 학습 step’ 범위로 묶는다. 원고의 캡션과 주를 붙인다.

### 동일한 내용을 두 방식으로 표현한 짧은 예시 · 검토안

자료는 위 라이팅 플랜의 P2이며, 원자료는 M1·M2에 연결되어 있다. 기존 섹션 S8의 메모리 관리 설명 일부를 비교하며, 새로운 설명 목표를 가진 섹션을 추가하는 예시는 아니다.

#### 결과보고서형

**필요한 티처 모듈만 GPU에 적재한다.** 체크포인트를 CPU에서 읽은 뒤, 선택한 증류 경로에 필요한 모듈을 남겨 GPU로 옮긴다.

- **LM만 사용:** 이미지 인코더와 텍스트 디코더를 적재한다.
- **LM과 ITM 사용:** 여기에 텍스트 인코더와 ITM 헤드를 추가로 적재한다.

#### 논문형

티처는 선택한 증류 경로에 필요한 모듈만 GPU에 적재하도록 구성하였다. 체크포인트를 CPU에서 읽은 뒤 필요한 모듈을 선별해 GPU로 옮겼으며, LM만 사용할 때는 이미지 인코더와 텍스트 디코더를 적재하였다. ITM을 함께 사용하는 경우에는 텍스트 인코더와 ITM 헤드를 추가로 적재하였다.

두 표현은 CPU 로드 후 모듈을 선별한다는 순서와 경로별 모듈 구성을 동일하게 유지한다. 결과보고서형은 선택지의 차이를 불렛으로 드러내고, 논문형은 같은 비교를 연결된 문장으로 설명한다. 실제 스킬에서 두 버전을 항상 함께 출력하도록 요구하는 것은 아니다.

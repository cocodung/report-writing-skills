# 실행 시나리오

평가 대상 에이전트에는 해당 시나리오의 요청, 시작 상태, 지정 자료만 제공한다. 기준 실행에는 구현 계획·설계 스펙·루브릭·대상 스킬을 제공하지 않는다. 스킬 실행에는 대상 SKILL.md와 그 스킬이 가리키는 패키지 참조를 제공한다. 두 실행은 새 문맥과 같은 모델·추론 설정을 사용하고, 생성물은 `.work/validation/<case>/<run>/`에 둔다.

## B-1 · 원자료에서 글감과 짧은 작성안 만들기

- 시작 상태: 신규 문서. 승인된 작성 조건·brief·spec·writing-plan이 없다.
- 자료: `tests/fixtures/kiosk/materials.md`
- 최초 요청:

> 이 자료로 팀의 개발 결과보고서를 준비하자. 독자는 제품 책임자다. 가독성을 중시하고 피규어는 만들지 말자. 기능 변경과 성능 중 무엇을 중심에 둘지는 아직 고민 중이다. 우선 글감과 짧은 작성안을 잡아줘.

- 핵심 강조점을 묻는 경우의 후속 응답:

> 중심은 방과 시간을 함께 선택하도록 흐름을 바꾼 이유와 구현이야. 관측 결과는 그 뒤에 제한을 포함해 보여주고, 추가 평가는 계획으로 남겨.

- 원자료에 없는 통합 동기와 승인 범위를 확인하는 경우의 보완 응답:

> 원자료에 없는 동기를 추가할 필요는 없고, 확인된 화면 구성 변화와 최종 확인 유지 이유 중심으로 잡아줘. 지금은 작성안 검토만 하는 것이고 스펙 진행을 승인한 것은 아니야.

실제 B-1 비교 실행에서는 같은 의미를 다음과 같이 구체화해 양쪽에 동일하게 제공했다.

> 원자료에 없는 방·시간 통합 동기를 새로 넣을 필요는 없어. 확인된 화면 구성의 변화와 최종 확인을 유지한 이유를 중심으로 작성안을 확정해줘. 관측·제한·추가 평가의 구분은 유지하자. 이전 응답은 보존하고 이번 응답은 response-scope.md에 저장해줘. 스펙으로 진행하라는 승인은 아직 아니고, 지금은 전체 작성안을 검토할 수 있게 준비해줘.

- 허용 출력: 실행별 폴더 안의 응답 원문과 `brief.md`, `materials.md`, `state.md`.
- 관찰 초점: 의도·관측·계획의 구분, 전체 흐름, 최초 불확실성 확인, 자료 접근 보존, 승인되지 않은 다음 단계의 확정 방지.

질문 개수나 특정 문구는 통과 조건이 아니다. 최초 응답이 질문 없이 완성안을 제시하면 후속 응답을 전달해 반영 결과도 보존한다. 원자료에 없는 통합 동기를 묻는 것은 정당한 자료 확인이며, 위 보완 응답은 비교 실행 양쪽에 동일하게 제공한다.
